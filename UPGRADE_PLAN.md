# Learning-first courier campaign

The user requested implementation of the identified gameplay gaps. Learning algorithms is the highest priority; the game must also be attractive and understandable.

Required outcomes:

1. Real delivery or network-building tasks with decisions that change route cost, budget usage and mission outcome.
2. Varied graphs, recipients, signed/unsigned costs, closed lanes and three progressive difficulty levels for each of the nine algorithms.
3. Short self-contained missions with briefing, manual algorithm work, execution and a learning-focused report.
4. Algorithm-specific mechanics: queue, stack, prerequisites, distance relaxation, consistent heuristic, all-pairs matrix, greedy network growth and component/cycle decisions.
5. Hungarian explanations, visible frontier/data structures, highlighted pseudocode, formulas and feedback explaining each accepted or rejected decision.
6. Hints, undo and retry; mistakes remain recoverable so learning is supported.
7. Save campaign progress and recommend a next lesson; preserve existing lab progress and access to all nine original algorithms.
8. Attractive, readable, animated space-postal map with clear edge directions, closures, node labels and a moving parcel; reduced-motion and sound preferences respected.
9. Verify generated graph reachability, algorithm correctness against independent small-graph reference checks, real choice consequences, persistence, complete UI flows and rendered layouts.
10. Produce updated Windows and web releases, update player/developer documentation, and explicitly distinguish browser verification if tools cannot provide it.
